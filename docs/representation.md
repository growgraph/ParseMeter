# What each converter hands downstream: structure beyond the markdown

Scope: the benchmark scored one markdown string per converter. A knowledge-graph pipeline
can also take each converter's native structured output, which may keep page furniture,
footnotes, tables, figures, equations, captions and headings as typed elements with page
and box provenance instead of flattening them into prose. This page records what each
converter's own representation offers, at the version we benchmarked, and what the
markdown we scored kept of it. Claims about the native model come from the installed
source in each arm's `.venv` (cited as path:line; read statically, nothing was run for this
page). Claims about the markdown come from our outputs in
`out/<arm>/docs/`. GROBID runs from a docker image, so its column
draws on the TEI files the arm saved (`out/grobid-default/assets/*/grobid.tei.xml`) and the
GROBID documentation. "static" means the claim was read from code and not confirmed on a
real document; "unverified" means no source settled it.

Path prefixes in the Evidence list: `ARMS` = `arms`; `SP(x)` =
`ARMS/x/.venv/lib/python3.12/site-packages` (after `uv sync` in that arm); `OUT` =
`out`.
