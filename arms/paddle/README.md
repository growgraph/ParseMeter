# paddle arm

- Version: paddleocr 3.7.0, paddlex 3.7.2, paddlepaddle 3.2.2 (CPU wheel), Python 3.12.
- Install: `uv sync` (deps `paddleocr[doc-parser]==3.7.0`, `paddlex[genai-client]==3.7.2` (OpenAI client for the VLM server), `paddlepaddle==3.2.2`) + the llama.cpp binary for `vl` (below).
  paddlepaddle 3.3.1 (latest) fails on CPU with oneDNN on: `NotImplementedError: ConvertPirAttribute2RuntimeAttribute not support [pir::ArrayAttribute<pir::DoubleAttribute>]` in the layout detector, so the pin is the newest 3.2.x.
- Models (`~/.paddlex/official_models/`, source HuggingFace): PP-StructureV3 set 1.8 GB before VL (PP-DocLayout_plus-L, PP-DocBlockLayout, PP-OCRv5_server det/rec, PP-FormulaNet_plus-L, SLANeXt/SLANet_plus + RT-DETR-L table cell detectors, PP-LCNet classifiers, UVDoc); VL adds PP-DocLayoutV3 126 MB plus either the GGUF (`~/.cache/huggingface/hub/models--PaddlePaddle--PaddleOCR-VL-1.6-GGUF`, 1.7 GB, `vl`) or the Paddle weights (`PaddleOCR-VL-1.6`, 1.8 GB, `vl-native`); 3.8 GB total under `~/.paddlex` now.
- License: Apache-2.0 (code and model weights).
- Server mode: `paddlex --serve --pipeline PP-StructureV3` / `paddleocr` serving docs (basic serving via PaddleX); VL can also use an external VLM server (`vl_rec_backend` = vllm/sglang/fastdeploy/mlx-vlm/llama-cpp-server + `vl_rec_server_url`).
- Common settings: `device="cpu"`, `cpu_threads=12`, `enable_mkldnn=True`, `PADDLE_PDX_MODEL_SOURCE=huggingface`, `PADDLE_PDX_DISABLE_MODEL_SOURCE_CHECK=True`. Both pipelines rasterise pages and OCR from pixels (no text layer).
- Variants:
  - `structurev3` — `PPStructureV3(use_doc_orientation_classify=False, use_doc_unwarping=False)` (the PaddleOCR quick-start settings for documents); pages joined with `concatenate_markdown_pages(...)["markdown_texts"]`. With the pipeline's default UVDoc unwarping pre-pass on, born-digital pages came back warped and many lines OCR'd as dropped-letter noise (`d rree e rr …`), so the pre-pass is off.
  - `vl` — `PaddleOCRVL(pipeline_version="v1.6", vl_rec_backend="llama-cpp-server")`: the official `PaddlePaddle/PaddleOCR-VL-1.6-GGUF` (1.7 GB: model + mmproj) served by a vendored llama.cpp `llama-server` (b11324 ubuntu-x64 CPU build in `bin/`, fetch with `cd arms/paddle/bin && curl -sL https://github.com/ggml-org/llama.cpp/releases/download/b11324/llama-b11324-bin-ubuntu-x64.tar.gz | tar xz`). `run.py` starts it in `make` on a free port (`--temp 0 --parallel 4 --ctx-size 32768 --threads <physical cores>`, log `arms/paddle/llama-server.log`) and stops it at exit/SIGTERM; client concurrency 4, OpenAI client timeout raised to 3600 s via `paddlex_config` (`genai_config.client_kwargs.timeout`). Layout (PP-DocLayoutV3) still runs in Paddle. Pages joined with `restructure_pages(merge_tables=True, relevel_titles=True, concatenate_pages=True)`.
  - `vl-native` — same pipeline on the default native Paddle VLM backend (float32 dynamic graph, ~1.5 cores busy): 834 s for ONE page in a test; impractical, kept only for completeness.
  - llama.cpp threads: decode collapses when llama-server threads exceed free physical cores — `llama-bench` on this model under background load: 12 threads 0.4 tok/s, 6 threads 2.2, 4 threads 14 (pp128: 27 / 49 / 68 tok/s). Default is one thread per physical core (6 here), override with `ARM_LLAMA_THREADS`. A first `vl` smoke with 12 threads ran 48 min and failed on a 600 s client timeout.
- Smoke (natcomm-2020, 7 pages, heavily shared machine — 6-core/12-thread laptop CPU with another arm running): structurev3 990 s (141 s/page; a marker llama-server was also running), 6.3 GB RSS, setup 29 s; vl 553 s (79 s/page), 2.6 GB RSS + llama-server, setup 5 s. Expect several times faster on an idle machine; the server-size OCR/formula models dominate.
- Output notes (structurev3): title `#`, section heads `##`; inline LaTeX for chemistry (`$\mathsf{C a T i O}_{3}…$`, spaced letters); figures as centred `<div><img src="imgs/…"></div>` HTML with captions in `<div>`; running head order shuffled (`DOI`, title, `ARTICLE`, `OPEN`); author line partly garbled where ORCID badges sit; drop-cap paragraph reordered (`P large oscillator … erovskites are …`); OCR typos (`guantum`, `eficient`); running footers/page numbers dropped by default (`markdown_ignore_labels`).
- Output notes (vl): cleanest of the paddle variants — title `#`, `##`/`###`/`####` heads after `relevel_titles`, author superscripts as inline LaTeX (`Zhou $ ^{1,2,6} $`), unicode subscripts (`CaTiO₃`), citations as `$ ^{1-4} $`; running header block (`ARTICLE`, DOI, `OPEN`) kept at top, running footers dropped; figure panels split into many centred `<div><img …></div>` crops with panel letters as separate `<div>`s; drop cap split (`P erovskites`).
